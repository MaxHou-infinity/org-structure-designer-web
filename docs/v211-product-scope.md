## 0. 一句话定位

v2.1.1 是 **「岗位化」地基版本**（对齐 v209-v300-version-plan §4），把 OrgCompass 的数据心智从 **「部门—员工」两级** 升级为 **「部门—岗位—员工」三级**。给用户的一句话承诺：

> **现在，你能把编制落到具体岗位上、把员工套进岗位，一眼看清「哪个岗位空着、哪个岗位超编、谁还没进图」，并把你手里那张完整的编制 / 成本 / 职级表一次性导入——不再逐部门手录编制、逐人弹窗填职级。**

这句话里藏着四个产品动作：**落位**（编制下沉到岗位）、**套岗**（员工套入岗位，人岗匹配显式化）、**看缺口**（岗位级空岗/超编 + 成本，服务招聘 BP）、**一次导全**（富字段导入替代手录）。

> 本版本**不做**：胜任度评分与红黄绿灯（v2.2.0）、AI 分析功能（本版本只做「数据就绪」）、岗位级 N 场景对比矩阵。用户看到的是「岗位模型能落地、能导入、能看缺口」，而不是「排兵布阵看板」。

## 1. 用户可感知的产品形态

### 1.1 岗位视图：组织树向下钻到岗位

**现状缺口**：组织树只有部门节点，员工直接挂在部门下（`Department.employees`）；「岗位」只是 `Employee.title` 一个自由文本字段，不参与任何计算、不约束编制。HRBP 的「岗位」信息今天散在员工表里，系统无法回答「这个部门下有几个岗位、每个岗位多少编制、空了几个」。

**目标形态**（复用现有 `DepartmentCard`/`OrgChart` 的钻取与定位交互）：

- **部门节点可展开到岗位层**：岗位（Position）是挂在部门下的「编制名额容器」。画布上部门卡片内新增岗位条目行，默认折叠在部门内，点击部门或「岗位」标签展开。
- **单条岗位行展示**：`岗位名称 · 序列/职级带宽 · 编制名额 · 实际在岗 · 状态灯`。状态灯沿用现有红黄绿语义（空岗=黄/红、满编=绿、超编=红/黄）。
- **员工套入岗位**：员工从「挂在部门」变为「挂在部门下的某个岗位」。画布上员工标签出现在其所属岗位行内；未套岗位的员工不显示在岗位行内，而是进「人岗匹配抽屉」（§1.2）。
- **岗位编制直接可编辑**：在岗位行上直接改编制名额（对齐现有 `onUpdateHeadcount` 的交互心智，从「部门级」换到「岗位级」）。

> 关键产品判断：**岗位视图不是新增一张独立表，而是把「岗位」插进用户已经熟悉的组织树里**。用户的心智是「部门里有几个岗位、每个岗位几个人」，产品要顺着这个心智往下钻，而不是另开一个平行视图让用户重新学。

### 1.2 人岗匹配如何呈现：进图 / 未进图 / 超编

**状态语义（产品侧，规则细节以 t1 为准）**：

| 状态 | 用户可理解的含义 | 本版本是否落地 |
| --- | --- | --- |
| **进图** | 员工已套入某个岗位 | ✅ 落地 |
| **未进图** | 员工在名册里，但没套入任何岗位 | ✅ 落地 |
| **超编** | 岗位实际在岗人数 > 岗位编制名额 | ✅ 落地 |
| **不胜任** | 员工与岗位匹配质量差 | ❌ 推迟 v2.2.0（依赖胜任度引擎），本版本仅预留字段、不渲染 |

**呈现方式**：把现有 `UnassignedEmployeesDrawer`（v2.0.5「未入架构员工」抽屉）**升级为「人岗匹配」抽屉**，作为唯一入口：

- **三个分组**：`未进图`（名册里没套岗位）、`超编岗位`（列出哪些岗位超编、多了几个人）、`待定`（数据缺失无法判定，如员工没有岗位信息）。
- **归因可追溯**：每条未进图员工能点回画布定位；「为什么没进图」给一句可读原因（超编挤不下 / 未套岗 / 岗位未配置编制），**不自动判「不胜任」**（那是 v2.2.0 的活，本版本不下这个断语）。
- **与现有「未入架构」的关系（需向用户讲清）**：v2.0.5 的「未入架构」=「员工没挂在组织树里」；本版本的「未进图」=「员工没套进岗位」。**两者并存但层级不同**：先看「是否进树」（架构），再看「是否套岗」（人岗匹配）。产品建议保留「未入架构」作为第一层提醒，把「套岗」作为第二层细化，抽屉内两段式呈现，避免老用户觉得「功能被换掉了」。

### 1.3 招聘缺口与成本视图：入口与形态

**现状**：`computeL3` 已产出部门级 `gap`/`gapCost`，`HealthDrawer` L3 展示「编制 vs 实际 vs 缺口 + 成本」。缺的是「岗位级」颗粒度，以及一个**面向招聘 BP 的独立入口**。

**目标形态**：

- **独立入口**：顶栏 + 健康度抽屉头部各加一个「招聘缺口」入口（对齐 v2.0.9「场景对比」的双入口做法）。有岗位数据即可点，无岗位数据提示「先导入岗位/编制」。
- **分组视图**：默认**按部门分组**，可切换到**按岗位**（平铺所有空岗/超编岗位）。**按序列分组后置**（见 §4.2）。
- **每行**：`岗位名称 · 所属部门 · 编制 · 实际 · 缺口（+空岗/−超编）· 缺口成本 · 状态灯`。顶部汇总卡：`总空岗岗位数 · 总缺口人数 · 总缺口月成本`。
- **导出**：招聘缺口表可**导出 Excel**（部门、岗位、编制、实际、缺口、缺口成本、状态），供招聘 BP 据此形成 JD 需求依据（对齐 v300 §3.2.5「招聘 BP 直读需求与缺口」的第一步）。

> 产品判断：招聘缺口视图是 v2.1.1 里**唯一一个「面向新角色」的产物**（招聘 BP 首次成为显性用户）。它不必做成独立看板，先做成「健康度抽屉里的一张可导出表 + 汇总卡」即可，招聘 BP 拿走的是数字和 Excel，不是一整套新 UI。

### 1.4 富字段导入：一次导全，替代手录

**现状**：`parseEmployeeExcel` 只读姓名/工号/职级/部门路径；编制靠逐部门手录，目标职级靠逐人 `window.prompt`（v209-v300-version-plan §2.1 明确标注为「半成品」）。这是 HR 侧「数据字段对齐」的最大断点。

**目标体验**：

- **员工 Excel 可选列**：`岗位名称 · 编制（岗位级）· 个人成本 · 目标职级 · 直接上级/汇报线`。缺省列**不阻断导入**，走降级（无岗位列 → 派生「未定岗」默认岗位；无成本 → 沿用现有职级成本映射；无目标职级 → 该员工不参与职级差距分析）。
- **可选「岗位表」独立 sheet（进阶路径）**：`岗位名称 · 所属部门 · 编制名额 · 序列/职级带宽`。用于一次录入「一个岗位多个编制名额、岗位带宽」这类员工表装不下的信息。
- **产品决策（主路径 vs 进阶路径）**：**员工表内嵌岗位列为主路径（零学习成本，一张表搞定）**；岗位表 sheet 为可选进阶（有明确岗位体系的企业才用）。导入校验 + 错误解释沿用 v2.0.8 护栏（哪一行哪一列错了、怎么改），不静默吞错。

> 一句用户话术：**「把你 HR 系统里导出的那张表直接丢进来，编制、成本、职级、岗位一次到位。」**——这是本版本最直接、最有感知价值的体验改进。

## 2. 面向用户的验收标准清单

> 每条 **可核对 / 可观测**，验收动作写在 `[验收]`。覆盖：岗位级编制、人岗匹配状态、富字段导入、`.orgproj` 迁移、招聘缺口视图、桌面端无回归。

### 2.1 岗位级编制正确性

- **P1** 部门可展开到岗位，每个岗位能显示并编辑**编制名额**；岗位级编制汇总正确（部门编制 = 部门下各岗位编制之和）。
  - [验收] 建「研发部」下设「前端工程师(2)/后端工程师(3)」两个岗位，确认部门编制汇总为 5、两岗位各显示 2/3，改任一岗位编制后汇总实时更新。
- **P2** 空岗率 / 缺口 / 成本改为**岗位级**计算后，与旧的部门级结果**可解释一致**（不出现数字无来由跳变）。
  - [验收] 把旧的部门级 headcount 迁移到「默认岗位」后，空岗率与迁移前一致；再拆分岗位，确认按岗位级重算、结论可追溯。

### 2.2 人岗匹配状态

- **M1** 员工能套入/移出岗位；套入后出现在该岗位行内，移出后回到「未进图」分组。
  - [验收] 把 1 名员工拖入「前端工程师」岗位，确认其出现在岗位行、且从「未进图」列表消失；再移出，反向验证。
- **M2** 「未进图」抽屉正确分组：未套岗 / 超编岗位 / 待定，每条可定位到人/岗位。
  - [验收] 构造「1 人未套岗、1 岗位超编 1 人、1 人岗位信息缺失」，确认三个分组各就各位、可点回画布。
- **M3** 超编判定正确：岗位实际人数 > 编制名额时标超编并给出「多几人」，不把「未配置编制」当超编。
  - [验收] 岗位编制=2、实际=3 → 超编「+1」；岗位编制未填 → 显示「未配置编制」而非超编。

### 2.3 富字段导入回归

- **I1** 员工 Excel 带 `岗位名称 / 编制 / 个人成本 / 目标职级 / 直接上级` 列时，导入后各字段落到正确实体，与系统内数字一致。
  - [验收] 用一张含上述列的 Excel 导入，确认岗位创建/套岗、岗位编制、个人成本、目标职级、汇报线全部正确；`test_employee_import.xlsx` 场景无回归。
- **I2** 缺省列**不阻断导入**并给出降级提示（无岗位→未定岗、无成本→职级成本映射、无目标职级→不参与职级分析）。
  - [验收] 用旧版「仅姓名/工号/职级/部门」的 Excel 导入，确认成功、员工落「未定岗」默认岗位、无报错。
- **I3** 可选「岗位表」sheet 能独立录入多个岗位与编制名额、并与员工表岗位名对齐（同名岗位聚合）。
  - [验收] 导入「岗位表」后，部门下出现对应岗位与编制；再导入员工表引用同名岗位，确认员工套入、不重复建岗位。

### 2.4 `.orgproj` 旧文件迁移无感

- **C1** 用 v2.0.x 保存的项目文件在 v2.1.1 打开，**无损迁移**：原有部门、员工、部门级 headcount 全部保留，headcount 归入「默认岗位」，不凭空增减数字。
  - [验收] 打开 v2.0.10 的 `.orgproj`，确认部门/员工/编制原样、空岗率与迁移前一致；再保存，确认 v2.1.1 结构正确。
- **C2** 迁移后的 `.orgproj` 可被旧版本打开（向下兼容）或给出明确「数据模型版本升级」提示，不静默损坏。
  - [验收] 用 v2.1.1 保存后再用旧逻辑校验 JSON 结构，确认无破坏性字段（以 t2 迁移方案为准）。

### 2.5 招聘缺口视图

- **R1** 招聘缺口视图能按部门/按岗位汇总缺口与成本，数字与 L3 缺口一致；顶部汇总卡正确。
  - [验收] 构造 3 个空岗岗位 + 1 个超编岗位，确认缺口人数、缺口成本、空岗/超编分类正确，与健康度 L3 对得上。
- **R2** 缺口表可导出 Excel，列完整、可二次透视，与屏幕数值一致。
  - [验收] 导出后用表格工具打开，确认部门/岗位/编制/实际/缺口/缺口成本/状态列齐全、数值一致。

### 2.6 桌面端与无回归

- **T1** macOS / Windows（Tauri）打包后，岗位视图、人岗匹配抽屉、招聘缺口、富字段导入全程本地运行，无联网、无遥测（沿用本地优先边界）。
  - [验收] `npm run tauri:build` 后双端打开 `.orgproj` 走完整流程，确认与 Web 行为一致、无回归。
- **T2** 单场景下现有健康度抽屉 L1/L2/L3、场景对比、管理层报告**不受岗位化影响**；未配置岗位时旧功能照常（岗位层默认折叠或显示「未定岗」）。
  - [验收] 只建部门不建岗位，打开健康度抽屉，确认 4 项指标照常、L3 编制/缺口仍可用（走部门级默认岗位口径）。

## 3. 优先级与范围边界（做 / 推迟 / 明确不做）

### 3.1 做（v2.1.1 交付）

| # | 范围 | 说明 |
| --- | --- | --- |
| 1 | **岗位（Position）实体 + 组织树岗位视图** | 编制从部门级下沉到岗位级；部门节点展开到岗位；岗位行可编辑编制、套岗 |
| 2 | **人岗匹配状态机 + 抽屉升级** | 进图/未进图/超编三态可判定可展示；升级 `UnassignedEmployeesDrawer`；「不胜任」仅预留字段不渲染 |
| 3 | **富字段导入** | 员工 Excel 增列岗位/编制/成本/目标职级/汇报线；可选「岗位表」sheet；缺省降级 + 护栏 |
| 4 | **招聘缺口与成本视图** | 岗位级缺口 + 成本，按部门/岗位分组，汇总卡 + 导出 Excel |
| 5 | **`.orgproj` 无损迁移** | 旧文件 headcount 归「默认岗位」，不增减数字，向下兼容 |

### 3.2 推迟（进 v2.2.0 或后续）

| 范围 | 理由 |
| --- | --- |
| **胜任度引擎**（领导力评分 → 分值/Gap → 红黄绿灯、员工业务/单兵能力） | v2.2.0 专属，需先补 `v220-competency-design.md`（定义债先清） |
| **「不胜任」自动判定** | 依赖胜任度引擎；本版本只预留匹配质量字段，不自动下「不胜任」断语 |
| **岗位级 N 场景对比矩阵** | 场景模型刚加岗位维度，先稳定「基线 vs 单目标」；岗位级多列矩阵待岗位模型稳定后再做（对齐 v2.0.9「先做 1 vs 1」的克制） |
| **按序列分组的招聘缺口汇总** | 先做部门+岗位两级；序列维度依赖序列主数据规范，后置 |
| **行业/企业阶段基准** | 长期挂起（v209-v300-version-plan §8 已判定「先做阶段，行业留后」） |

### 3.3 明确不做（边界约定，延续本地优先红线）

- **不做 AI 分析功能**：本版本只做「数据就绪」（稳定 ID、结构化枚举、显式关联、原始值/派生值分离），**不在 UI 暴露任何「AI」入口、按钮或结论**（见 §4）。
- **不引入黑盒评分 / 方案排名 / 「推荐」断语**：延续「只陈述事实、不替用户下结论」红线；人岗匹配只报状态，不自动评优劣。
- **不新增云端同步 / 账号 / 遥测**：全部本地处理（沿用 v2.0.8 起边界）。
- **不做破坏性变更**：`.orgproj` 与导出产物兼容（§2.4）。
- **不把「未配置编制」伪装成「超编/不胜任」**：缺数据就显示「未配置/待定」，不猜。

## 4. 未来 AI 能力的产品愿景与门面

### 4.1 用户未来会「问 AI 什么」（产品愿景，非本版本功能）

本版本不给用户看 AI，但要让数据**将来能被 AI 可靠回答这些问题**：

| 用户未来的问题 | 需要的产品语义 | 本版本预留 |
| --- | --- | --- |
| 「这个组织哪里不健康、为什么」 | 组织树 + 岗位 + 编制 + 人岗匹配的完整主数据 + 可解释口径 | 岗位实体 + 状态机 + 口径说明不变 |
| 「这个岗位该招什么样的人、招几个」 | 岗位画像（序列/职级带宽/编制缺口/历史在岗） | 岗位字段结构化（序列、职级带宽、编制名额） |
| 「哪些岗位缺人最急、补人成本多少」 | 岗位级缺口 + 成本 + 优先级 | 招聘缺口视图的数据层 |
| 「谁和岗位不匹配、差在哪」 | 人岗匹配状态 + 胜任度 Gap | 匹配质量字段**预留**（胜任度数据 v2.2.0 才填） |

### 4.2 产品侧的「门面」原则（如何不越界、不夸大）

- **本版本零 AI 暴露**：用户看不到「AI」两个字，也不承诺「智能诊断」。数据建模的 AI 前瞻性（稳定 UUID、显式外键、结构化枚举、时态、原始值 vs 派生值分离、脱敏导出）由 t3（ai-data-expert）落字段级要求，**产品侧只保证这些预留不破坏现有本地优先体验、不引入云端依赖**。
- **一条产品红线**：任何「为 AI 预留」的字段/约束，**不得**变成用户当前的负担（不加必填、不加导入阻断、不加新的手动维护动作）。AI 前瞻是「留口不实现」，不是「让用户为未来填表」。
- **未来接入形态的克制预判**（供 t3 对齐，不本版本设计）：本地优先产品未来接 AI，最可能是「用户主动导出脱敏主数据 → 本地小模型/云端模型分析 → 结论回贴」。因此产品侧要求：**主数据要能结构化、脱敏、字段级授权导出**——这与「数据可分析但可控」一致，且不冲突本地优先。

## 5. 风险提示与用户话术

### 5.1 产品风险

| 风险 | 表现 | 缓解（产品要求） |
| --- | --- | --- |
| **数据模型改造让老用户「数字变了」** | 编制从部门级搬岗位级，用户误以为「数据算错了/丢了」 | 迁移规则「部门 headcount 归默认岗位、不增减数字」；迁移后空岗率与迁移前一致；话术讲清「编制还是你的编制，只是落到更细的岗位上」 |
| **「进图」与「未入架构」语义打架** | 老用户分不清「没进树」和「没套岗」 | 抽屉两段式呈现，先架构后套岗；保留「未入架构」概念，新增「未进图」细分，不替换 |
| **岗位表 vs 员工表对不齐** | 两处岗位名不一致 → 重复建岗位/套错岗 | 岗位名聚合对齐（同名合并），导入校验提示「岗位未在岗位表出现」；默认走员工表内嵌，岗位表仅进阶 |
| **富字段导入缺省被误当 0** | 无成本/无目标职级 → 被当成「0 成本 / 无差距」 | 缺省降级明确「不参与该分析」而非「0」；沿用 v2.0.8「缺失不伪装成结论」纪律 |
| **用户期待「人岗匹配=胜任度评分」** | 看到「匹配状态」就以为系统在评「人配不配得上岗」 | 本版本只报「进图/未进图/超编」，不渲染「不胜任」；话术明确「胜任度评分在下一个版本」 |
| **误以为「AI 分析」已经上线** | 数据建模留口被外部解读为「已有 AI 能力」 | 本版本 UI 零 AI 暴露；对外只讲「数据更结构化、更好算」，不讲「AI」 |

### 5.2 用户话术（可直接用，不夸大）

**岗位化定位（首次使用）**：
> "这次升级是把你的组织从「部门—员工」细到「部门—岗位—员工」：编制落到具体岗位，员工套进岗位，一眼看清哪个岗位空着、哪个超编、谁还没进图。"

**富字段导入**：
> "把你 HR 系统导出的那张表直接丢进来，编制、成本、职级、岗位一次到位，不用再逐部门、逐人手录。"

**旧项目迁移（安抚老用户）**：
> "你之前录的编制一个都不会少——它们会归到各部门下的默认岗位里，你可以再往下拆到具体岗位。空岗率等指标口径不变，数字对得上。"

**招聘缺口视图**：
> "这是一张给招聘用的缺口表：哪个部门、哪个岗位缺几个人、按成本算缺口多少钱，可导出 Excel 直接做招聘需求依据。"

**边界（防误读）**：
> "人岗匹配现在只告诉你「进图/未进图/超编」的客观状态，不替你判断谁胜任、谁不胜任——胜任度评分在下一个版本。所有数据只在你本机处理，不会上传。"

> ⚠️ **避免的表达**（会反噬信任）：「AI 帮你诊断组织」「系统判定谁不胜任」「自动推荐招人优先级」——这些既不是本版本能力，也违反「不黑盒、不替用户下结论」的既有纪律。
